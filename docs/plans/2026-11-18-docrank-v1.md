# docrank v1 — the plan

A public Claude Code plugin (`nacorga/docrank`, MIT, English) that packages the
portable part of TraceLog's Claude Code setup: guard hooks that enforce the
method instead of asking for it, read-only judges, gates before a push, docs
that outrank code, and the working principles. One file per repository,
`.claude/docrank.json`, adapts it; an `init` skill proposes that file by
reading the repository. TraceLog adopts it after v1 is stable, in a plan of its
own.

Source of every piece: `tracelog/.claude/`, `.githooks/`, `tools/` and
`~/.claude/{CLAUDE.md,hooks/context-handoff.sh}`, inventoried 2026-11-18.

## Decisions closed

- Scope: everything portable (below). Language English. MIT. `nacorga/docrank`.
- Per-repository adaptation through `.claude/docrank.json`, one source; no
  copies written into the repository except what Claude Code cannot load from
  a plugin (the optional git hook).
- Built apart; TraceLog untouched until v1 is published.
- Runtime: Node ≥ 20 built-ins only, no npm dependency at run time. Shell
  scripts that need `jq` are ported to `.mjs` when touched. macOS and Linux;
  Windows is out of v1.
- Nothing reaches GitHub (repo creation, push, marketplace) without the
  user's word.

## How the slices relate

Slice 1 lands first: every other slice reads the config through its loader.
After it, slices 2–8 stand alone and each opens against `main`; at most two
build at once. Slice 9 needs all of them. Heavy (Opus): 3 and 7.

## Slices

- [ ] **1 · Skeleton and config.** `.claude-plugin/plugin.json`,
  `marketplace.json`, LICENSE (MIT), README stub; `lib/config.mjs` loading and
  validating `.claude/docrank.json` (hand-written validation, every error names
  the key); `docs/config.md` documenting each key once; a vitest self-test
  harness for the plugin itself (dev dependency only). Before any code, verify
  in code.claude.com and record in `docs/harness-facts.md`, with the URL:
  `${CLAUDE_PLUGIN_ROOT}` in hook commands; whether plugins can wire
  `WorktreeCreate`, `Stop`, `SessionEnd` and `SessionStart` `additionalContext`;
  the hook input's `agent_type`; plugin agents' `mcpServers` and `skills`
  frontmatter; skill `allowed-tools` with a plugin path; whether
  `subagents/agent-<id>.meta.json` and the `~/.claude/projects/<slug>` naming
  are documented. A fact not documented is marked so, and the slice that
  depends on it says what it does without it.
- [ ] **2 · Bash guard and gates record.** Port `dangerous-guard.sh` to
  `.mjs` with every TraceLog literal moved to config (branches, `batch/*`, tags,
  DB-volume rules become `extraDeny` regexes); the "push needs a gates record"
  check moves into this hook, so no git hook is required; generic case suite
  (`run-hook-suite`) with its `gh` stub rewritten on neutral names.
- [ ] **3 · Agents: read-only, dispatch, re-check, protocol.** *(heavy)*
  `agent-types.mjs`, `guard-read-only.mjs`, `guard-dispatch.mjs`,
  `guard-recheck.mjs`, `last-report.mjs` (ported from `.sh`); `judge-protocol`
  rewritten generic with the re-check count read from config, not stated twice;
  `dispatch-guardrails` rewritten as a public default block (no remote, no
  amend, run the real gate, final message is the report, read-only add-on,
  hand-over sweep), extendable by the repo. Tests from the generic describe
  blocks of `claude-harness.test.ts`.
- [ ] **4 · Gates.** `gates` skill and `run-gates.mjs` running `gates[]` in
  order, stopping at the first failure, PASS/FAIL per gate, logs in a temp dir,
  named `jobs` only when asked, record of the clean HEAD that passed; optional
  `.githooks/pre-push` that `init` offers to write.
- [ ] **5 · Edit-time guards.** `guard-paths`, `format-on-edit`, `guard-plan`,
  `guard-message`, `doc-drift` on stop, each from config and each with tests.
- [ ] **6 · Worktrees and pull requests.** `worktree-create`,
  `prune-worktrees`, `watch-pr`, `guard-pr`, judges routing (`docrank judges
  <range>`), and the `ship` skill's generic core.
- [ ] **7 · Docs as spec.** *(heavy)* `spec-arbiter` generic (precedence ladder
  from config; "code never wins", code/doc defect labels, report shape);
  `surface-reviewer` generic with its browser MCP pinned; CLI checks
  `docrank check sections` and `docrank check drift-pairs`; `doc-facts` readers
  exported as a small library; `doc-lint` skill over `docGroups`.
- [ ] **8 · Principles and hand-off.** SessionStart injection of the working
  principles (autonomy, planning, verification, recovery, engineering)
  generalized from `~/.claude/CLAUDE.md`, the closing line and its language
  from config; `context-handoff` with threshold and location from config;
  optional `link-memory`.
- [ ] **9 · Init, README and trial.** `init` skill that reads a repository
  (branches, package manager, test/lint/build scripts, docs tree) and proposes
  `docrank.json` for the user to confirm; README with install, the config
  table linked to `docs/config.md`, and what each guard refuses; a trial in
  the two repositories the user chose, each in its own worktree on a
  `chore/docrank-trial` branch cut from its integration branch, plugin loaded
  with `--plugin-dir` (nothing installed globally), walking init → a refused
  dangerous command → gates → a guarded push → a judge review:
  - `~/Desktop/projects/eclizen/code/eclizen/` — not yet read: the sandbox
    refuses the path (`Operation not permitted`).
  - `~/Desktop/projects/callmenacho/code/porfolio/` — Next.js, npm
    (`package-lock.json`), branch `main` only, remote `nacorga/porfolio`,
    scripts `lint`, `typecheck`, `build`, `test:smoke`, a 36-line `CLAUDE.md`,
    no `.claude/`.

  Nothing from a trial is pushed or merged into those repositories without the
  user's word. Then, with the user's word, create `nacorga/docrank`, push and
  publish the marketplace.
